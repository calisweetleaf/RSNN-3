# Repository scope

**Engagement mode:** EDIT — repository harness and evidence surfaces first;
runtime repairs only when the active packet authorizes them.

## In scope

- Make this repository executable for one arriving coding agent.
- Preserve and route the customizable LQT implementation.
- Reconcile source, tests, historical reports, and supplied whitepapers.
- Repair implementation gaps that block a truthful completion claim.
- Maintain reproducible build/test evidence.

## Out of scope until explicitly dispatched

- Replacing LQT with another format.
- Treating RTA as an alias for LQT.
- Importing generic Somnus architecture or provider-specific agent rules.
- Declaring the RTA mathematics complete from structural round-trip tests.
- Rewriting historical reports instead of recording current evidence.
- Installing system packages or depending on network access during the gate.

## Current evidence boundary

The supplied archive contains implementation, tests, examples, and historical
reports, but not the canonical whitepapers referenced by those reports.
Whitepaper compliance is therefore **not verifiable** in the current snapshot.
